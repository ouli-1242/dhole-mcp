==================== web_read
-- url: URL to fetch
-- urls: URLs (parallel; one row each in `results`; check is at most 10)
-- extraction_type: Format: markdown (default), html (raw markup), text, article, structured, or check (changed-since-last-fetch; urls= batch, max 10).
-- css_selector: Narrows extracted content. HTML only - on XML/JSON/plain text the whole document comes back and the summary says so.
-- max_content_chars: Content cap in chars (500-200000; default from DHOLE_DEFAULT_CONTENT_CHARS). The rest stays reachable via offset/next_offset.
-- timeout: Whole-call budget in ms (default 30000; 25000 with actions; max 120000), shared by the HTTP retries; one HTTP attempt caps at 30s (timeout_applied names the figure). On a document URL it is spent on the DOWNLOAD, and a download gets one attempt.
-- cache_ttl: Cache seconds (default 3600). 0 = force fresh.
-- force_fetcher: Pin one tier, skipping auto-escalation: 'http' = fast, no JS/bot walls; 'stealthy' = anti-detect browser.
-- anti_detect: Browser stealth level: off, basic (canvas + WebRTC), auto (the tested default, answers Cloudflare), aggressive (auto + every resource). Omit = cred_defaults, else auto.
-- offset: Char offset to resume a truncated page; take it from next_offset.
-- pages: PDF only: '1-5' or '1,3,5-7'. Narrows what is EXTRACTED, not what is downloaded; pick ranges from table_of_contents.
-- password: PDF only: password for an encrypted PDF.
-- focus: Return only blocks matching this query. Applied after the cache, so it does not re-fetch; re-pass the same focus when paginating. Which scorer runs it, and what it costs: focus_engine.
-- focus_mode: Shape of the focus answer: 'filter' (default) keeps every block past the relevance cut; 'best' returns only the highest-scoring block plus its heading. Requires focus.
-- focus_engine: Which scorer runs focus: 'bm25' (default, keyword overlap) or 'neural' (a local cross-encoder, needing the reranker model). Per-page cost: sys_guide(topic='behavior').
-- schema: CSS-driven structured extraction instead of markdown: {properties: {...}} (a JSON string is accepted). Which keys are read, first match vs "type": "array", per-element grouping, the invented-keyword trap and the record ceilings: sys_guide(topic='behavior', section='Structured extraction').
-- confirm: Approval for a sensitive action on this call - today only cdp_url: an attach is refused with cdp_authorization_required unless that host's approval is younger than 30 days, and nothing executes without it. False (default) approves nothing.
-- session_id: Carry cookies across calls under this name (1-64 chars: letters, digits, . _ -). Covers both tiers; values never leave the process.
-- ignore_robots: Skip the robots.txt check for this call (default false = comply). True only where you have the site's permission.
-- check_login: Model-free login probe on the settled browser page; returns login_check (DOM signals + cookie NAMES, never values). Live-only: null on HTTP-tier results and on cache hits.
-- cdp_url: Attach the user's Chrome over CDP: rides that profile's logged-in cookies, skips the HTTP tier and public cache; answers say cdp_attached=true. Attach needs confirm=true per host (30 days).
-- headers: Your keys win, key by key, over what dhole synthesizes. Refused by name, each with its door: cookie / authorization / proxy-authorization -> cred_defaults, user-agent -> the TLS profile, if-* -> extraction_type='check'. anti_detect='off' sends yours alone; caps: sys_guide(topic='behavior').
-- include_links: Also return outgoing links, classified as citations / navigation / external, with a primary_source hint (default false).
-- max_links: Per-list cap for include_links (1-100; default 30/20/20); links.total_found and links.is_truncated report what it hid.
-- include_media: Also return up to 20 image URLs found on the page in .media (default false).
-- include_headers: Also return this response's status line, headers and redirect endpoints in metadata (default false). Set-Cookie comes back as cookie NAMES only; a redirect chain is walked with HEAD, and the call skips the cache because stored headers describe an earlier fetch.
-- save_to: Write this response's BYTES to this file instead of extracting text. Parent must exist; an existing file is refused, never overwritten. Returns one receipt line (metadata.saved_to/bytes/sha256); skips cache and extraction. Pairs with max_save_bytes.
-- max_save_bytes: Ceiling for save_to: default 268435456 (256MB), cap 1073741824 (1GB). Over it nothing is written and the size is reported. The 50MB extraction cap does not apply to a save_to download.
-- nested_selector: Two layers in one call: a CSS selector on THIS page naming the elements to follow; each one's href (its own, a descendant's or an ancestor's <a>) is fetched and nested_fields read there.
-- nested_fields: What to read on each second-layer page: [{'name':'作品','selector':'.work a','type':'array'}] or {'作品':'.work a'}. 1-12 fields; array = every match. Field rules and the carry-over trap: sys_guide(topic='behavior').
-- nested_max: How many of this page's unique links to expand (default 8, max 30). Links the cap hid are truncation=nested_budget; duplicates and href-less matches are counted separately.
==================== web_act
-- url: The page to act on. One per call - a chain is written against one DOM.
-- actions: ONE action key per object: [{scroll:3},{wait:1000}]. Keys: click,fill,read,press,hover,drag,wait,scroll,wait_selector,snapshot,screenshot,submit,upload,dialog,tab,select,navigate,pdf,evaluate; fill=text,press=key,drag=to,upload=files,dialog=answer,select=option,pdf=save_to,evaluate=expr.
-- extraction_type: How the post-action page is read back (default markdown; also html, text, article, structured).
-- max_content_chars: Max chars of that content (default 40000); the action receipts are never cut by it.
-- focus: After the chain, return only blocks relevant to this query instead of the whole page.
-- timeout: Whole-call budget in ms (default 25000 - sized to beat a typical 30s host MCP timeout; raise it when your host allows more. max 120000).
-- anti_detect: Stealth rungs per web_read.anti_detect; omit = cred_defaults, else auto.
-- session_id: Act inside this named session, so the login it holds is the state the page starts from. Names only, never values.
-- cdp_url: Attach a running Chrome (its own logged-in profile) and act there; an attach needs confirm=true per host (30 days).
-- confirm: A submit reads it INSIDE the action: {"submit": {..., "confirm": true}} - a top-level confirm does NOT release it. Top-level it gates the first CDP attach. Only on the user's explicit yes.
-- check_login: Model-free login probe on the settled browser page; returns login_check (DOM signals + cookie NAMES, never values).
-- headed: Run this chain in a VISIBLE window so the user can watch and step in (log in by hand, one CAPTCHA). Default hidden. A hidden browser already up on that profile is neither taken over nor closed - refused (browser_busy). Consequences: sys_guide(topic='config', section='Variables by scenario').
-- pin: Keep this page for the next call with pin=true on that session: it acts on THIS page, no re-navigation, so the captcha you just read is the one you answer. Needs session_id=.
==================== web_request
-- url: Absolute http(s) URL to send this request to. One URL per call - a write is not a batch.
-- method: POST / PUT / PATCH / DELETE / HEAD (case-insensitive). GET is refused: web_read owns the cache, the escalation ladder and the archive fallback.
-- body: Request body (cap 256KB). A dict is sent as a form, or as JSON when content_type says json; a string is sent as-is. HEAD takes none.
-- content_type: Content-Type for body, e.g. application/json or application/x-www-form-urlencoded. A dict body defaults to the form encoding unless this says json.
-- extraction_type: How the answer is read back: markdown (default), html, text, article or structured. A server answering a write with JSON still gets that JSON extracted.
-- timeout: Whole-call budget in ms (default 30000, max 120000); one HTTP attempt caps at 30s (see timeout_applied).
-- confirm: Required true for POST / PUT / PATCH / DELETE: a write acts only on the user's explicit yes, and stored credentials for the host ride along. HEAD needs none.
-- headers: Headers to send, winning key by key over what dhole synthesizes. The same three families are refused here by name and for the same reason - see web_read.headers.
-- include_headers: Also return this answer's status line and headers in metadata (default false). Best on HEAD probes: Content-Length / Content-Type / cache headers, no body. Set-Cookie returns cookie NAMES only.
-- session_id: Carry and store cookies under this session name (1-64: letters, digits, . _ -): a login POST's Set-Cookie lands in the jar, and the next web_read with the same id rides it. Values never come back.
==================== web_crawl
-- url: Start URL (crawl stays on this domain)
-- focus: Query: crawl the links relevant to this and focus-filter each page.
-- search: Filter URLs by keyword (URL path + title where a title was read).
-- sitemap: Where the URL map comes from: true | 'auto' (default) | false. A tri-state, so the strings a serialized client sends are accepted too.
-- max_pages: Pages to fetch (1-40, default 10). The first budget a crawl hits.
-- max_depth: Hops from the start URL (0-5, default 2). 0 = the start page only.
-- concurrency: Pages in flight at once (1-5, default 3). Waiting between requests to one host is that host's robots.txt Crawl-delay, not a knob here.
-- path_include: Keep only these path subtrees: '/docs' keeps /docs and everything under it, NOT /docs-old.
-- path_exclude: Drop these path subtrees: '/docs-old' under an include keeps nothing.
-- max_content_chars_per: Per-page content cap (500-20000, default 8000).
-- max_total_chars: Whole-run content cap (1000-200000, default 60000; 0 = no cap). When it bites the crawl stops before the next batch and the summary names the pages left.
-- cache_ttl: Cache seconds per page (default 3600). 0 = force fresh.
-- force_fetcher: Pin one tier for every page, skipping auto-escalation: 'http' fast but no JS/bot walls, 'stealthy' the anti-detect browser.
-- timeout: Per-PAGE budget in ms (default 30000, max 120000); the whole crawl stops at deadline_ms; one HTTP attempt caps at 30s.
-- deadline_ms: Whole-crawl budget ms (default 25000; timeout= per page); soft cap
-- ignore_robots: Skip the robots.txt check for this call (default false = comply). True only where you have the site's permission.
-- focus_engine: Which scorer runs focus here: 'bm25' (default, cheap) or 'neural' (the local reranker model; asking without it is refused, not downgraded).
-- resume_token: Pass back web_discover's plan_id:0 verbatim; next_resume_token continues where the budget bit.
-- selector: With resume_token=: project every planned page to this CSS selector.
-- schema: With resume_token=: JSON-schema projection of every planned page.
==================== web_discover
-- url: Start URL (the map stays on this domain)
-- sitemap: true = the site's index only, 'auto' = index then link walk, unset/false = link walk.
-- max_pages: URLs to expand through (1-40, default 10).
-- path_include: Keep only these path subtrees: '/docs', or '/docs/*'.
-- path_exclude: Drop these path subtrees.
-- search: Filter the map by keyword (URL path + title where one was read).
-- max_total_chars: Chars one map page may carry (1000-200000, default 60000; 0 = no cap). A map's row count is set by the site, so this is the knob that sizes a page.
-- resume_token: Pass back plan_id:<rows shipped> verbatim to get the map rows the budget held back - same map, no re-walk, no re-pay.
-- timeout: Whole-call budget in ms (default 25000 - sized to beat a typical 30s host MCP timeout; max 120000, outside 1-120000 refused). On a map this IS the clock: it bounds the call and the single request sitemap=true needs, so a slow index wants this raised, not a retry.
==================== web_search
-- query: Words to search for. Optional only with mode='find_similar'.
-- url: The page to find similar pages of (mode='find_similar').
-- mode: Rerank: 'auto' (default) uses the local reranker when it can; 'neural' demands it (a refusal is named, not disguised); 'find_similar' needs url=.
-- max_results: Results to return (1-50, default 6).
-- page: Result page, 0-10 (default 0).
-- cache_ttl: Cache seconds (default 300). 0 = force fresh.
-- engines: Narrow the pool, max 18 names: the 12 above plus keyed engines that need a key (sys_guide(topic='behavior', section='web_search')).
-- sources: Pools (default ['web']): 'web','news','academic','qa','code','community'. Verticals are keyless; omitting 'web' searches only them and refuses engines=. Their rows never add to engines_consensus.
-- sort: 'relevance' (default) or 'newest': newest orders rows with a stated publish day newest-first; undated rows stay after.
-- site: Restrict to one domain.
-- exclude_sites: Drop results from these domains.
-- location: ISO country code ('US'), optionally with a region suffix ('US-CN'). Anything else is refused rather than guessed at.
-- language: 2-letter language code.
-- region: Engine region, passed through as given and folded into the cache key. Omitted, it is derived from location + language.
-- freshness: Time window: 'day', 'week', 'month' or 'year' only; anything else is refused. No engine takes a finer or absolute range.
-- after: 'Newer than' a date: widened to the narrowest engine preset that covers it; date_filter reports what was actually sent.
-- before: Upper bound, applied per row (not sent to engines): provably newer rows are dropped and counted in date_coverage; undated/relative rows stay.
-- fetch_content: Pull the top hits' full text inside this same call (default false) instead of returning snippets.
-- fetch_schema: {properties: {...}} applied to the pages fetched by fetch_content, instead of their markdown - the same shape rules as web_read's schema.
-- fetch_min_consensus: fetch_content only: keep only hits corroborated by >= N independent index families (min 2; 0 = off). Skipped URLs are in consensus_skipped.
-- min_relevance: 0-1 cutoff on the NORMALIZED rerank score. Below it results are dropped, not re-ordered.
-- min_raw_relevance: 0-1 floor on the reranker's RAW score - the one that can call a whole round irrelevant. fetch_hint reports the raw span.
==================== web_research
-- query: The question the evidence must speak to; it is also the focus= filter applied to every page read.
-- max_sources: Sources to read (1-5, default 3).
-- per_source_chars: Chars per source after focus (500-20000, default 4000).
-- timeout: Whole-call budget in ms (30000-300000, default 120000), split across the sources.
==================== web_recall
-- query: Words to recall by (any language; CJK matches by character bigram).
-- limit: Rows to return (1-20, default 8), best first.
==================== cred_defaults
-- set: Keys: proxy, profile, cdp, allow_private, anti_detect, auth, cookies. auth / cookies need a "host" BESIDE them (one name or a list) naming their site.
-- unset: Key names to forget, every host scope of them together. An unknown name is an error, never a silent no-op.
-- show: true = report the store and change nothing. A call with no arguments at all does the same thing.
==================== sys_state
-- show: State classes to report without touching them: cache|engine_state|sessions|cred_defaults|cdp_hosts|config|models|all.
-- clear: State classes to erase (config and models are show-only), or one open session id; cdp:host=<name> revokes one CDP approval.
-- confirm: true for an erasure you would not notice as it happened (sessions|cdp_hosts|all).
==================== doc_parse
-- file_path: Absolute or relative path to a local file. Supported: .html/.htm/.xhtml, .docx, .xlsx/.xlsm, .csv/.tsv, .pdf, .md/.markdown/.txt, .json/.yaml/.yml, .pptx, .odt
-- cwd: Base directory for a relative file_path. Ignored for absolute paths.
-- encoding: Charset for .html/.csv (e.g. 'gbk', 'big5', 'shift_jis', 'cp1252'). Leave unset to auto-detect; pass it when the result is mojibake.
-- offset: Character offset to continue a truncated read (default 0). When is_truncated is true, the Next offset this tool prints is what you pass back here - same paging contract as web_read.
-- pages: PDF only: '1-5' or '1,3,5-7'. Narrows what is EXTRACTED, not what is downloaded; pick ranges from table_of_contents.
-- password: PDF only: password for an encrypted PDF.
==================== feed_read
-- urls: One or more RSS/Atom feed URLs
-- max_items: Max entries per feed (default 20; 0 = all)
-- timeout: Per-fetch budget in ms (default 20000, max 120000).
-- since: Incremental poll: keep entries published at or after this (ISO-8601 '2026-09-20', RFC-822, or relative '3h'/'3d'/'2w') - pass the previous call's newest published value. items_older_than_since counts what it dropped; undated entries are kept, never dropped.
==================== sys_guide
-- topic: Volumes: start = one-page route map + hard constraints. manual = full SKILL.md. call = writing a call (placement, patterns). fields = reading a response. behavior = deep per-tool behavior. fix = a failure to diagnose. config = a knob. recipes = a multi-step task. Filename is an alias.
-- section: One heading inside the volume, matched case-insensitively (e.g. 'actions', 'PDF', 'engine matrix'). No match answers with the headings that exist.
